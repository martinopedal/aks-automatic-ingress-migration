### Wave2 ADR-004: Toolkit posture on preview features (2026-05-13)

Created ADR-004 addressing two Microsoft preview features: App Routing Gateway API implementation and AGC ALB Controller AKS add-on.

**Context:** Microsoft shipped two previews that materially change AGC migration story. App Routing add-on now supports Gateway API (Istio-based, not AGC). AGC ALB Controller available as AKS add-on (auto-creates identity in MC_ resource group, collides with ADR-002 IaC scope).

**Recommendation (Proposed status, awaiting user decision):**
1. Do NOT recommend preview features as default path. SLA exclusion per [Azure preview supplemental terms](https://azure.microsoft.com/support/legal/preview-supplemental-terms/) means production migrations cannot accept preview risk.
2. Do NOT ship IaC for AGC add-on. Auto-created identity in MC_ resource group violates ADR-002 and Iris's identity boundary. Document as alternative with warnings.
3. DO document App Routing Gateway API as non-AGC alternative. Positions toolkit clearly: we are the AGC path.

**Key insight from PR #55 citation failure:** Voice profile had citation rule but lacked enforcement teeth. Agents bypassed by citing wrong sources or inventing lists. Added worked examples to `.squad/skills/voice-profile/SKILL.md`:
- ✓ Good citation: inline, verifiable, exact list copied from source, access date.
- ✗ Bad citation: invented list, wrong source cited, no access date, unverifiable.

**Rule strengthened:** "Every factual claim about retirement dates, default behaviour, version-specific behaviour, region lists, supported feature flags, or SLAs links inline (not in a trailing References section) to a primary source: learn.microsoft.com URL or upstream GitHub release page. Lists copied from a source must match the source exactly. If a claim cannot be cited from public material, do not make it."

**Lesson:** Skill files need worked examples showing the failure mode, not just abstract rules. "Cite sources" is too weak. "Cite sources inline with exact lists and access dates, see worked example" has teeth.

### 2026-05-12: Persistent session logging rule established

**Rule:** Every session must write all in-flight work to `.squad/` proactively before session ends. This is a permanent directive from the user: "always ensure everything is written into squad so we can break off sessions without issues".

**Mechanism:** 
- SQL todos (session-scoped, do not survive) are NOT the durable handoff format.
- Inbox files in `.squad/decisions/inbox/` are the durable format.
- Coordinator writes inbox file proactively, then spawns Scribe (background) to merge and commit.
- Next session reads merged decisions to understand what was in-flight.

**When to write inbox file:**
1. Compaction signal (summary header in next user turn)
2. User suggests session may end ("end session", "I'm out", "let's pick this up later")
3. Multi-step plan that may not finish in current turn budget
4. User idle for extended period
5. Spawn manifest exists but agents not yet launched

**Inbox file content:**
- Decision or plan in plain prose
- Exact file paths (input, output)
- Source references (skills, other repos, MS docs)
- Commands or scripts next session must run
- Status of each work item (planned, in-progress, blocked, done)
- Ownership (Sage, Atlas, Iris, Sentinel, Forge)

**For multi-agent spawns:** Write spawn manifest to inbox BEFORE launching agents. If spawn fails or session dies, next session knows what was intended.

**Full reference:** `.squad/decisions.md` decision #10.

### 2026-05-13: Wave 4 ADR-004 Accepted, AKS Automatic add-on path documented

PR #67 pivoted ADR-004 from Proposed to Accepted with a more nuanced posture than my wave 2 draft proposed. The new posture: document the AGC ALB Controller AKS add-on path as first-class for AKS Automatic users, but do NOT ship Terraform or Bicep IaC for it.

Reasoning grounded in the AGC FAQ finding from wave 3: AKS Automatic + AGC requires the add-on (Helm install unsupported on Automatic). Without documenting the add-on path, the toolkit cannot serve its declared audience (AKS Automatic users planning migration). At the same time, shipping IaC for a preview feature whose add-on auto-creates identity in `MC_*` would break the ADR-002 parity contract.

The middle path serves both audiences: standard AKS users keep the full Helm IaC path; AKS Automatic users get a documented, citation-grounded enablement sequence in `docs/aks-automatic-path.md` with all `az` commands quoted from the canonical [add-on quickstart](https://learn.microsoft.com/azure/application-gateway/for-containers/quickstart-deploy-application-gateway-for-containers-alb-controller-addon).
