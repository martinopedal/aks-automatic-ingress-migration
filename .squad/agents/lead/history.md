## Learnings

### @copilot output quality patterns (2026-05-12)

Observations from reviewing 10 PRs generated by @copilot:

1. **Gateway API version compliance**: All manifest PRs correctly used `gateway.networking.k8s.io/v1` (GA), not `v1beta1`. Good adherence to `.github/copilot-instructions.md`.

2. **ALZ Corp defaults**: Hello-world sample used `azure-alb-internal` as expected. Catalog used external for demonstration, which is reasonable for a translation reference.

3. **Workload Identity**: Identity wiring runbook (#26) correctly avoided SP secrets. Used federated credentials with proper namespace/SA subject format.

4. **Case sensitivity gap**: PR #29 had a case mismatch in check names (`Analyze` vs `analyze`). @copilot likely inferred the name from the workflow `name:` field rather than the actual check display format. This is a common pitfall when GitHub Actions matrix jobs append suffixes.

5. **Incomplete file sets**: PR #37 created an entry point that referenced a schema file via `$ref`, but the referenced file was not included. @copilot may have been following a pattern without verifying all referenced files exist.

6. **Documentation quality**: README updates, threat models, and runbooks had proper MS doc citations. No em dashes observed. Style compliance was good.

### Recommendation for future @copilot prompts

- For branch protection or check name references, explicitly state: "use the exact check name as displayed in the GitHub Actions UI, including case and matrix suffixes."
- For schema or module references, add: "verify all referenced files exist in the PR before submitting."
