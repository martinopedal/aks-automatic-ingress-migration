### 2026-05-12: Persistent session logging rule established

**Rule:** Every session must write all in-flight work to `.squad/` proactively before session ends. This is a permanent directive from the user: "always ensure everything is written into squad so we can break off sessions without issues".

**Mechanism:** 
- SQL todos (session-scoped, do not survive) are NOT the durable handoff format.
- Inbox files in `.squad/decisions/inbox/` are the durable format.
- Coordinator writes inbox file proactively, then spawns Scribe (background) to merge and commit.
- Next session reads merged decisions to understand what was in-flight.

**When to write inbox file:**
1. Compaction signal (summary header in next user turn)
2. User suggests session may end ("end session", "I'm out", "let's pick this up later")
3. Multi-step plan that may not finish in current turn budget
4. User idle for extended period
5. Spawn manifest exists but agents not yet launched

**Inbox file content:**
- Decision or plan in plain prose
- Exact file paths (input, output)
- Source references (skills, other repos, MS docs)
- Commands or scripts next session must run
- Status of each work item (planned, in-progress, blocked, done)
- Ownership (Sage, Atlas, Iris, Sentinel, Forge)

**For multi-agent spawns:** Write spawn manifest to inbox BEFORE launching agents. If spawn fails or session dies, next session knows what was intended.

**Full reference:** `.squad/decisions.md` decision #10.
